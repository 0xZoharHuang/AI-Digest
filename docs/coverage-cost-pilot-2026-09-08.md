# 全量初读与分级核查：第一轮隔离实验

日期：2026-09-08。所有实验位于本机 runtime 的 `validation/`，没有修改生产代码路径、配置、分包、定时服务或 Wiki；没有真实推送。DeepSeek 组未执行：在本项目配置和当前环境未找到项目可用凭证，没有向其他提供商发送材料。

## 结论

数千条全量初读在当前 Codex/Luna 配置下可执行，现有研究包数量不是模型处理记录数量的硬上限。但轻量化不能直接充当可靠过滤器或等深度研究替代品。本轮发现了真实漏读、引用上下文遗漏和过早停止问题，结论是继续隔离验证，不上线替换。

## 实验一：3,766 条真实日数据全部初读

输入来自 `runs/2026-09-08/attempt-0001/02_routing/units.jsonl`，保持每条记录及完整 payload 内容，仅移除明确的部分存储/采集字段。正文、作者、引用、媒体、未知 payload 字段保留，不截断长文本。输出是 signal/kind/短原文锚点；没有联网，没有做跨包归属，也没有写研究报告。

运行模型：Luna/medium；118 次调用；3,766/3,766 条输出；原始文件哈希不变。

| 项目 | 历史生产首轮标注 | 新全量初读 |
| --- | ---: | ---: |
| 输入 token，包含缓存 | 4,818,598 | 3,446,590 |
| 缓存输入 token | 718,848 | 913,664 |
| 输出 token | 150,060 | 161,767 |

输入减少约 28.5%，非缓存输入减少约 38.2%，输出反而增加约 7.8%。工作不完全等价：历史首轮含批内分组，新初读不分组。不得据此声称完整 Phase 2 降本相同比例；也不能换算成相同比例的 Codex 订阅额度节省。

保护后的结果：2,856 present、889 unclear、21 chatter。550 条锚点未通过严格连续原文检查，其中 415 条为空，94 条原判 present。空锚点不都代表幻觉，但这说明让模型抄原文会制造额外输出负担和伪不确定性，不宜成为简易分类的必要合同。

证据：`validation/light-intake-20260908-all/{experiment.json,decisions.jsonl,receipt.json}`。

### 128 条配对样本

按来源固定抽样，选择时不看候选输出。使用同一个 Luna/medium、同一提示和输出合同，比较完整输入与精简输入；另以 Sol/medium 完整原文产生独立参考，不展示候选答案。

| 项目 | Luna 完整输入 | Luna 精简输入 | Sol 独立参考 |
| --- | ---: | ---: | ---: |
| 输入 token | 219,663 | 161,656 | 227,188 |
| 输出 token | 5,813 | 5,217 | 5,997 |
| 原始 signal 与参考一致 | 118/128 | 119/128 | 非人工金标 |
| kind 与参考一致 | 113/128 | 119/128 | 非人工金标 |

样本输入减少约 26.4%，但字节上限造成完整输入 5 批、精简输入 4 批，批次上下文也不同。因此是流程对照，不是字段投影的纯因果消融。模型间一致率不是准确率，也不是弱信号召回率。

样本中“镜子为什么需要 Wi-Fi”的吐槽被 Luna 初判闲聊，Sol 判断为产品体验问题；缺上下文保护将其保留为 unclear，没有排除。

证据：`light-intake-20260908-sample-{compact,full,reference}`。

### 全部 21 个 chatter 的人工检查与针对性复测

人工检查发现多个明确遗漏：当前帖仅有“欢迎加入”“值得读”或表情，但捕获的引用中有 FSD 在斯洛文尼亚获批、Hermes 插件构想、研究文章等信息。初读没有充分利用已给出的引用，并非这些信息不存在。

对这 21 个已检查的开发病例，把引用内容显式展开，并只返回 signal 标签；仍用 Luna/medium。19 条变为 present、2 条保留 chatter；明确发布线索被找回，但一些泛泛观点和笑话也变为 present，存在放宽阈值/引入噪声的风险。

这是选定失败案例上的回归实验，输入呈现和输出合同同时改变；不是独立留出集，不能将 19/21 解释为准确率或已证明的全量召回改善。调用用了 28,412 输入、753 输出 token。

证据：`light-intake-20260908-quote-regression/regression.json`。

## 实验二：同样 40 个包，有边界的来源核查

复用既有 40 包容量实验的入口材料及读者配置，沿用 Sol/medium。4 个独立 thread、每批 10 包、并发 2。每包以最多两份额外来源为初始提示目标，只输出短事实、资料缺口、已读 URL 和升级状态；没有完整研究文件套件。

“两份来源”是软提示，不是程序强制的工具限额。sufficient 只代表当前短事实足够有据，不代表完整研究完成。

| 项目 | 历史 40 包完整研究（20 包/任务） | 新 40 包有限核查 |
| --- | ---: | ---: |
| 输入 token，包含缓存 | 10,936,869 | 1,612,349 |
| 非缓存输入 token | 586,789 | 334,781 |
| 输出 token | 80,054 | 15,633 |
| 本次耗时 | 1,717.89 秒 | 358.87 秒 |

同样本非同期实验，联网内容及执行流程不同；不保证等深度。新流程非缓存输入少约 43%，输出少约 80.5%，但尚未包含后续升级研究的成本，不能当作完整混合系统节省率或每日 SLA。

40/40 有结果：17 sufficient、13 needs_deep、4 blocked、6 no_signal。即使接受这些初判，也至少还需处理 13 个深挖请求及资料阻塞问题；没有将 40 条短记录算成 40 篇深度报告。

### 来源审计与质量复核

按每个准确 thread ID 查阅本次会话，验证 cwd 和会话哈希，提取实际来源工具返回；共识别 24 次来源工具调用，不等于 24 个网页。初版汇总漏采 native web telemetry，错误默认值 0 已改为 null；旧回执保留为 `receipt.raw-v1.json`，不能引用其 0 宣称未联网。

Sol/medium 的来源辅助诊断：34 条 supported、6 条 uncertain；2 处 unsafe_stop；另有 3 个 no_signal 记录含缺失上下文，需要状态保护。诊断同时给了 40 条 signal_preserved，但它不等于端到端召回 100%，尤其不能掩盖 unsafe_stop。

实际问题包括：

- 没有播放/核查视频，却过早停止为 no_signal。
- Fedora 的材料中注明正式批准的是修订后的版本，核查未追到最终批准文本，就把提案条款写成当前政策。人工查看已采集的来源片段也确认了这一版本跳转。

部分主张证据 uncertain 也可能来自提取器漏采，不能全部说成模型编造。公开来源自述不是独立复现实验；评估不是人工金标。

证据：`bounded-checks-20260908-40/` 与 `bounded-checks-20260908-40-review/`。

## 下一步最小实验

1. 用显式引用上下文、仅标签或程序定位符的输出合同，做新的独立留出集对照；不要再要求模型抄一段文本来证明阅读。
2. 对关键上下文缺失、政策/版本跳转和未核实核心事实，阻止“完成/无信号”终止，保留待补全或升级状态。
3. 实际执行需要升级的深度研究，再算初读＋核查＋升级的总成本与报告质量，不能只报第一层省下的 token。
4. 获得项目专用 DeepSeek 凭证后再做同数据、同输出合同的第三组；不重写生产框架，不把其他项目凭证拿来使用。

研发验证：290 项已有/新增测试通过，Ruff/Mypy 通过。所有生产模块未修改；仅新增隔离实验脚本、一个输入保留测试和本说明。此次不部署。

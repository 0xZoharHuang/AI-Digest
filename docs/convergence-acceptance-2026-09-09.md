# Phase 2/3 收敛优化验收（2026-09-09）

## 范围与发布决定

目标是深度优先、每天最多15个独立研究thread，不设置token、工具调用或compaction次数门槛。
保留当前模型档位、最多6并发、20包上限及既有工作量加权分配。原始记录、历史报告、Wiki结构、
接收者与7点日程不变，不接入新提供商。本轮不再增加第三版算法/提示候选。

**Phase 2阅读视图保持关闭。** 两版候选虽有输入成本改善，但第三天出现具体错误合并；不能满足
“无新增严重错误合并”的门槛。**Phase 3精简研究合同默认关闭，最终成对复核记录单独存档。**
已观察到20包压力测试的来源归属回退，不能用平均分或完整台账抵消。默认保留生产研究合同。

独立保留的工程改进：冻结已调度任务清单；15任务/6并发/20包上限；禁止子agent；原thread恢复；
缺失thread身份时拒绝另建替代thread；已验证产物、共享输入及附件在正常返回和中断时均做哈希检查；
增补内部未成稿判断供brief区分资料不足与编辑取舍；仅记录compaction和用量，不控制Codex压缩。
新阅读视图、精简合同及manifest编译器保持独立默认关闭开关，旧任务按已冻结版本恢复。

## Phase 3验证

先使用40包回归＋20新包做正序/倒序20包压力测试。第一版精简合同暴露工具结果未展示后误判资料不足，
第二版补回工具结果读取与停止条件，未增设搜索或token上限。由于第一组20包已用于诊断，另冻结20包
最终留出，并排除相同身份/内容。第二版压力测试仍出现具体来源归属错误，结果不可视为通过。

再用**未改动的生产工作量估计器和加权器**冻结60包映射：11任务，大小为
8/1/8/8/7/8/6/5/6/2/1。基线与候选采用相同材料、同模型Sol/medium、相同映射及读者配置；
两组均60/60完成、无执行错误。未为了凑60包改变权重或扩大15任务预算。

| 生产加权正序 | 非缓存输入 | 输出 |
| --- | ---: | ---: |
| 基线 | 2,093,353 | 189,098 |
| 候选 | 2,405,028 | 192,173 |

候选没有在该实验降本，用户也未要求Phase 3按token淘汰；选择看证据和深度，不看篇数或长度。
来源工具返回按精确thread/cwd提取，抽取可能漏掉未被引用的镜像，人工复核不能只信模型判分。
例如服务犬Charlie叙事被初次判为无来源，但完整会话确实有搜索镜像文本；它仍只是来源主张，
不是独立事实确认。此类提取缺失不计为模型凭空编造。

真实中断恢复：同一thread `01a08191-e18f-74e3-b07b-dc8b72e30eb7`在15包验证后中断，
恢复后20/20完成，已验证的15包内容哈希均不变，观察到一次compaction。没有新增替代thread。
用量计数在resume时重置，已改为累计观测分段；约4,159,215输入、3,889,152缓存输入、30,466输出。
中断中的尚未上报计算可能缺失，故标为usage_complete=false，而不是假称完整精确计费。
